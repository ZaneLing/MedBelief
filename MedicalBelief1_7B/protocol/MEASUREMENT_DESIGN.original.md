# 医学信念轨迹：病例、捕捉函数、疾病概率与结果图设计

日期：2026-11-18。版本：测量设计v1。

**核心任务：同一个病人，证据逐组到来，记录模型每一轮、每一层对六种疾病的支持如何变化。** 最终疾病标签由数据源提供，放在评估端；模型只看已经揭示的资料。

本次已经完成：12例现有数据病例的选择与原始字段核对、131个累计证据前缀的准备、真实分词器边界检查、模型接口核对。本文件设计了后续深度测试需要的函数和交付物。**尚未加载模型做前向推理，没有新的疾病概率、激活或实验结果。**

先读第1—4节即可理解实验；第5节以后是实现时逐项照做的技术规格。

## 1. 最后要看到的是什么

以一个最终疾病标注为肺炎的病例为例，我们希望回答：

- 第几条证据后，肺炎超过了支气管炎或肺栓塞？
- 是中间层先转向肺炎，最后输出过几轮才跟上，还是整个模型同时转向？
- 如果后面又转错，是哪条证据触发、偏向了哪个疾病、发生在哪些层？
- 正确疾病的支持在加强，还是模型只是越来越肯定一个错误疾病？

我们保存一个三维结果：

```text
一位病人
  ├─ 第0轮：初始病情 → 第1层……第36层 → 六种疾病各有多少支持
  ├─ 第1轮：新增证据 → 第1层……第36层 → 六种疾病各有多少支持
  ├─ 第2轮：新增证据 → 第1层……第36层 → 六种疾病各有多少支持
  └─ 最后一轮：完整资料 → 第1层……第36层 → 最终诊断与内部状态
```

“医学信念”在这轮实验中具体落在**当前证据下，对候选疾病的相对支持及其变化**。最终输出、逐层读出、模块变化分别记录，便于把现象追到内部。

## 3. 一轮分成哪些测量时刻

### D：直接诊断

给出截至本轮的累计证据，关闭思考生成，要求从六类候选中选择。在助手准备输出诊断代码的位置捕捉全部层。

它回答：**在这个固定诊断提示下，模型现在更偏向哪个疾病？**

### R：思考之后诊断

给同一轮证据，允许模型生成思考；当它自然生成`</think>`时停止，追加同一诊断输出前缀，再捕捉全部层并读疾病分数。

它回答：**这一轮经过展开推理后，各层和最终疾病选择怎样变化？**

### P：开始思考之前的快照

在R分支的`<think>\n`之后，尚未生成思考内容时，额外保存隐藏状态，标记为`pre_reasoning`。此处下一词原本要生成思考文本，不能把六个答案代码的原始词概率直接解释为疾病概率。P快照用于后续经验证的状态读出，与D、R分开画。

若思考达到2048词元上限仍未自然结束，R标记为`thinking_truncated`，保留已有文本，不人工补结束符制造“思考完成”的分数。

**第一批主实验不把前一轮答案放回下一轮。** 每轮从累计证据重新计算，以观察证据本身的影响。后续加入真实旧诊断历史，另测自我承诺的影响。

## 4. 三种数字一起保存，概率才不会误读

六类候选编码为A—F，但真正读取的是分词器里带一个空格的` A`至` F`。代码对应哪种疾病由当条轨迹的映射决定；最后统一还原为疾病顺序。

真实分词器已经检查：

| 输出片段 | 词元ID |
|---|---:|
| ` A` | 362 |
| ` B` | 425 |
| ` C` | 356 |
| ` D` | 422 |
| ` E` | 468 |
| ` F` | 434 |

131个前缀×6种循环映射，共786个直接诊断输入均通过边界检查；长度204—792词元。[核验结果](protocol/token_boundary_audit.json)

设模型在诊断位置对整个词表输出分数`z`，疾病d对应的词元是`c(d)`：

1. **原始疾病分数**：`z[c(d)]`。用于看正确疾病与竞争疾病的分差。
2. **完整词表下的代码概率**：`p_code(d) = exp(z[c(d)] − logsumexp(z))`。它包含模型选择其他格式或文字的可能性。
3. **六种候选内部的相对支持度**：`q(d) = exp(z[c(d)] − logsumexp(z[c(A…F)]))`。这是疾病竞争曲线的主要纵轴。

再保存`candidate_mass = sum(p_code)`及`other_token_mass = 1 − candidate_mass`。低候选质量可能来自输出格式或其他文字倾向，不直接等于模型认为“资料不足”。

所有分数都取**温度1、未做top-k/top-p过滤**的原始输出，用float32稳定计算。思考文字的采样设置另外记录，不拿采样后的分布充当疾病支持度。

实际文本回答也另存：`conditional_top_disease`是六类分数的最高者；`generated_disease`是模型真正生成的合规诊断；格式不合规则记为缺失，不偷偷用最高分替它补答。

六类支持度是这项限定候选任务中的模型偏好。最终标签只用于评价它偏向得对不对。

## 5. 模型内部捕捉在哪里

已核对本机官方8-bit Qwen3-4B配置和MLX代码：[接口核对](protocol/model_interface_audit.json)。

| 项目 | 本机实际值 |
|---|---:|
| Transformer层数 | 36 |
| 隐藏向量长度 | 2560 |
| MLP中间维度 | 9728 |
| 查询注意力头／KV头 | 32／8 |
| 每个注意力头维度 | 128 |
| 词表大小 | 151936 |
| 输出头 | 与词嵌入共享权重 |

注意：这里的头维度不是`2560/32`。实现必须按实际配置使用128。

### 每层保存五个位置

在统一的诊断输出锚点，对每一层保存：

```text
r_pre     进入该层时的状态
attn_delta  注意力模块给出的增量
r_mid     r_pre + attn_delta
mlp_delta   MLP给出的增量
r_post    r_mid + mlp_delta
```

对应本机计算：

```python
attn_delta = block.self_attn(block.input_layernorm(r_pre), mask, cache=None)
r_mid = r_pre + attn_delta
mlp_delta = block.mlp(block.post_attention_layernorm(r_mid))
r_post = r_mid + mlp_delta
```

记录时调用原生模块，不用手算注意力替换正常推理。每层主记录形状为`[5, 2560]`，一个测量点共`[36, 5, 2560]`。第0层词嵌入作为可选基线单列，不把它计入36层。

主锚点是追加`Diagnosis code:`后的最后一个词元，尚未给出答案。固定的是语义位置，绝对词元下标会随证据长度变化；保存真实下标、完整输入ID、模板哈希与证据字符／词元范围。

可额外记录新证据末尾的位置，但它不与诊断锚点混用：自回归模型前面的词元看不到后面信息，旧证据词元的向量也不会因后来追加一句话自动重新包含未来内容。

### 正确调用输出头

本机模型是共享词嵌入输出头，使用：

```python
logits = model.model.embed_tokens.as_linear(model.model.norm(h))
```

不能假定存在`model.lm_head`。量化整数权重保持原样；native前向用既定精度，概率运算再转float32。只对选定位置计算完整词表输出，避免把所有输入位置的151936维输出都保存下来。

## 6. 怎样得到每一层的疾病支持度

### 第一条路线：固定输出头直接读

对每层`r_post`用同一个最终归一化和输出头，得到`z_layer[l]`，再按第4节计算疾病支持度`q_raw[l,d]`。同时记录每层候选代码的完整词表质量。

最后一层必须与真实模型前向的同位置logits一致。这是必做的工程核验。早层的直接投影提供观察窗口；是否已具有可用的诊断含义，要看后面的校准和对照。

### 第二条路线：经独立病例校准的读出

在独立训练病例的各轮前缀上，每层学习一个简单映射，预测模型在**同一轮、同一模式、同一前缀**的最终六类分数。采用带正则的线性映射或soft-label分类器，按病例做开发选择。

- 训练目标：当时模型自己的最终分数，不是病例真值，也不是看到未来全部证据后的答案。
- 每层只训练一次，之后冻结，同一条轨迹的所有轮次都用它。
- D和R分别校准；P若要读疾病分数，另建明确目标的预测读出，不能混作自然输出。
- 正则、温度等只在开发病例选择；最后一层直接使用真实输出，不用拟合分数替换。
- 校准集按病例划分，所有前缀与顺序变体一同分组；D和R的同一病人也不能跨训练和测试。

这是面向六种疾病的任务读出。它参考[Tuned Lens](https://arxiv.org/abs/2303.08112)逐层解码的思路，但不把六分类器称为完整词表Tuned Lens。两种路线并列报告；不挑一条更好看的曲线。

校准评价包括：与同轮模型最终分布的KL差异、排名一致性、相对只看文字基线的表现，以及随机标签对照。真值标签读出若后续添加，命名为`ground_truth_decodability`，与模型当时偏好分开。

## 7. 注意力和MLP怎么记录，怎么解释

### 注意力：它当前把信息分配到哪里

只读取诊断锚点作为query时，对输入词元的注意力，不保存完整`序列长度×序列长度`矩阵。

按本机实现计算Q/K投影、逐头RMSNorm、RoPE和mask，使用`head_dim**-0.5`缩放。32个查询头与8个KV头按原GQA分组对应。重新算出的注意力只用于旁路观测，不替代原生融合算子的输出。

将注意力按证据范围汇总，保存：

- 每层、每头分配给每一条已见证据的总质量。
- 按证据词元数除过的平均质量，区分“更长所以总量更大”。
- 系统说明、候选列表、诊断前缀、思考文本、特殊词元及其他位置的质量。

所有不重叠范围加起来应为1。不要只在证据之间重新归一化，隐去模型其实主要在看自己的思考文字。

### MLP：哪部分内部计算在推高哪个疾病

首批保存MLP对残差流的输出增量。更细的9728维门控激活，只在机制诊断模式或预定病例上追加。

对固定的两个疾病d1、d2，比较`r_pre → r_mid → r_post`各自经过同一读出后的分差变化，得到注意力阶段和MLP阶段的“投影分差变化”。每对疾病的比较对象在相邻步骤保持相同，不在每一步重新挑竞争疾病。

它用于定位候选模块。真正判断某模块是否造成转向，要在后续实施局部替换，并检查最终疾病分数随之怎样改变。

| `decode_layers_raw(bundle,model,code_map)` | `[36,2560]`层输出 | `[36,6]`及每层质量 | 同一最终norm和输出头；末层校验 |
| `fit_layer_readouts(train,development)` | 独立病例快照、同轮终端分布 | 冻结的各层读出和验证结果 | 无病例真值和未来终端答案作为目标 |
| `decode_layers_calibrated(bundle,readouts)` | 状态、冻结映射 | `[36,6]` | 用相同映射读每轮，不按轮重新拟合 |
| `compare_rounds(previous,current)` | 同病例同模式同映射两轮记录 | 更新量、排名变化、JS、激活变化 | 比较共同诊断锚点；未来内容不反填过去 |
| `evaluate_trajectory(records,gold)` | 整条轨迹、私有标签 | 命中、稳定、回退、错误竞争疾病 | 唯一接收gold做评价的阶段 |
| `estimate_module_score_change(bundle,pair)` | 模块前后状态、固定疾病对 | 每层attention/MLP投影分差变化 | 定位候选贡献，不直接宣称因果 |
| `write_observation(record,bundle)` | 元数据、张量 | JSONL、NPZ、哈希 | 原子落盘，可恢复；模型或协议变化换run ID |
| `plot_trajectory(case_records,metrics)` | 保存的真实分数与评价 | PNG、PDF和对应数值表 | 不把缺失轮补成0或填成正确疾病 |

### 主循环伪代码

```python
model = load_frozen_model(model_manifest)
for public_prefix in frozen_public_prefixes:
    direct = run_observation(public_prefix, mode="D", config=config)
    write_observation(direct.record, direct.capture)

    # 同一个累计证据前缀；不含D的回答，也不含以前各轮回答。
    reasoned = run_observation(public_prefix, mode="R", config=config)
    write_observation(reasoned.record, reasoned.capture)

# 全部模型运行完成后，评价程序才合并最终疾病标签。
metrics = evaluate_all(saved_records, private_gold_table)
```

## 9. 更新的量化指标

主要指标每个病例、每种模式分别计算；统计不把同一病人的17轮当作17位独立病人。

| 指标 | 具体定义 | 人话解释 |
|---|---|---|
| 单病更新量 | `Δq[t,l,d] = q[t,l,d] − q[t−1,l,d]` | 新证据把哪个病推高、推低，推了多少 |
| 正确疾病排名 | 在固定六类中对最终标签的排名 | 它离猜中还有几位 |
| 正确疾病领先幅度 | `q[y] − max(q[d≠y])` | 正值领先，负值被某个错误疾病压过 |
| 原始分差 | `z[y] − max(z[d≠y])` | 同时保留不受六类归一化掩盖的分数差 |
| 首次命中轮 | 第一次正确疾病独占第一的轮次 | 什么时候第一次转对 |
| 稳定命中轮 | 从该轮到观察结束始终正确领先 | 什么时候转对后保持住；仅对已观察范围成立 |
| 回退／恢复次数 | 正确→错误、错误→正确的次数 | 更多证据是在纠错还是带偏 |
| 熵 | `−sum(q log q)/log(6)` | 候选偏好分散还是集中 |
| 分布变化 | 相邻轮六类分布的JS散度 | 整体判断变动多大；与方向指标一起看 |
| 内部外部时差 | 某层首次／稳定领先轮减输出端对应轮 | 内部是否提前出现正确方向 |
| 证据敏感性 | 原顺序与对照顺序的同一终点分数差 | 信息相同，顺序是否改变终点 |

分数并列时不任意填“独占第一”。未命中设`null`并记录未达到；R缺失轮不能跳过后宣布“始终正确”。不同读出得到的层间时差分别报告，不混算。

## 10. 保存格式与资源预算

一个观察点由`case_id / round / mode / mapping_id / generation_seed / run_id`唯一定位。每次运行记录代码、病例、模板、权重版本及其哈希。

建议目录：

```text
runs/<run_id>/
  manifest.json              模型、协议、输入与源码版本
  observations.jsonl         每轮实际回答、状态、时间和分数摘要
  states/<observation>.npz   五阶段残差状态、输入ID、锚点
  scores/<observation>.npz   完整末层logits、逐层六类分数
  attention/<observation>.npz  注意力按证据汇总
  reasoning/<observation>.json  实际思考token与结束原因
  readouts/                  冻结读出、划分和验证结果
  metrics/                   逐病例指标及总体统计
  figures/                   疾病曲线、层×轮次热图、模块变化
```

| 张量／字段 | 单个观察点的形状或类型 | 保存约定 |
|---|---|---|
| `residual_stages` | `[36,5,2560]` | native为float16时按float16保存，阶段名另存 |
| `terminal_logits` | `[151936]` | float32存储，未经采样过滤 |
| `layer_candidate_logits` | `[36,6]` | float32，疾病顺序标准化 |
| `layer_candidate_support` | `[36,6]` | float32，标明raw或calibrated |
| `layer_candidate_mass` | `[36]` | 直接词表投影时保存 |
| `attention_group_mass` | `[36,32,J]` | J含所有证据和非证据区间；float32 |
| `input_ids`、`anchor_index` | `[N]`、整数 | 精确序列，不只保存文字 |
| `status` | 字符串枚举 | `complete/format_invalid/thinking_truncated/capture_failed`等 |

D与R最多262个诊断观察点，另131个P快照。每个诊断点五阶段残差约0.92 MB、末层logits约0.61 MB；D/R主数据约0.40 GB，连同P、注意力、解释文本与文件开销，先预留1—2 GB。不默认保存每层完整词表logits或每层完整注意力矩阵。

首批用本机已下载4B权重，收费模型API预算0美元。R最多`131×2048=268288`个思考词元，另有诊断短输出；真实运行时间先用3个病例的少量前缀实测再估计。本次仅准备材料和检查分词，实际新增模型API支出0美元。

## 11. 哪些对照先做

1. **输出代码对照：**当前已准备六种循环映射；先在`ddx_train_0857360`、`ddx_train_0875644`、`ddx_train_0868644`的初始、中间`floor(T/2)`、最终轮测试全部映射，共54个D评分点，含9个已有主条件点。每条轨迹内部映射固定，结果回到疾病名后再比较；这45个追加点不包含在主实验262个D/R观察点中。
2. **直接／思考后对照：**同一证据同时测D与R，明确变化来自新增证据还是本轮思考。R主种子20261118，温度0.6、top-p 0.95、top-k 20；若发现关键轨迹，在完整12例上追加第二种子，不只重试失败个案。
3. **顺序对照：**主哈希顺序和另外预先固定的顺序，对最终证据集合保持一致。中间不同轮只有已见集合完全相同时才作直接配对；否则说明它们看到的信息不同。
4. **历史对照：**累计证据主条件完成后，再加入各轮真实旧诊断，比较同病例的轨迹变化。
5. **内容对照：**重复某条已有证据、延迟预先选定的证据、加入等长度中性文字；避免把长度和位置变化全部当成医学信念变化。
6. **读出对照：**病例分组留出、文字基线、随机标签与未训练读出。[方法依据](https://aclanthology.org/D19-1275/)

12例首先验证测量是否工作。它们不用于训练高维读出。校准读出使用后续独立的fit病例；当前12例只展示raw轨迹及其读出质量，不能先在这12例上调到漂亮再称独立结果。

## 12. 正式运行前，必须通过的工程检查

| 检查 | 通过标准 |
|---|---|
| 来源与标签 | 12例原始CSV行、初始证据、分组和最终标签可逐一追溯；目前已通过准备检查 |
| 前缀泄露 | t轮仅出现0…t已见组；不含最终标签字段、隐藏鉴别诊断或未来组 |
| 分词边界 | `encode(frame + suffix) == encode(frame) + [code_id]`；D已通过，实际R逐次检查 |
| 正常／采集前向 | 同一精度、输入下，末层logits和argmax一致；记录最大误差；预定容差`atol=1e-3, rtol=1e-3`，失败先查采集实现 |
| 残差重建 | 保存的r_mid、r_post与实际加法一致；没有漏掉norm或残差 |
| 最后一层读出 | raw末层六类logits等于原生同位置输出头分数 |
| 概率运算 | 有限、非负、六类q和为1；`sum(p_code)==candidate_mass≤1`；不混入采样温度 |
| 注意力旁路 | 正确Q/K norm、RoPE、GQA映射和mask；重建加权V与融合算子在预定容差内一致，分组质量总和为1 |
| 恢复运行 | 同一版本相同输入不会重复写；换模型、提示、证据或源码用新run ID |
| 权重固定 | 运行前后参数清单／校验一致，没有优化器更新 |

FP16的比较在float32中计算误差。若融合内核导致旁路误差超限，首先保留原生诊断和激活，标记注意力旁路未通过；调整阈值需记录理由和开发对照，不能看到诊断结果后放宽。

### 本次实际发现并规避的旧索引问题

旧转换器把`initial_evidence_idx`保存为排序证据表的序号；旧环境和前缀生成器却把它当成展开后的atom位置。对4000个discovery病例进行代码映射核对，2960个会恢复成不同的证据ID。

例如序号213应还原为`E_218`，旧读法会落到`E_55`。新材料从原始CSV的`INITIAL_EVIDENCE`直接恢复，并与正确的证据序号表逐条核对。

这项发现属于数据接口审计，旧实验准确率需要另行重算才能判断影响。本次保留旧项目和旧结果，不沿用错误解码。核对记录已写入[设计清单](protocol/design_inventory.json)。

## 13. 第一轮结果怎样交付

每个病例至少交付：

1. **疾病竞争曲线：**横轴为证据轮次，纵轴为六类支持度；真实疾病加粗，新增证据列在下方。D和R分面显示。
2. **疾病领先图：**横轴为证据轮次，纵轴为模型层，颜色直接表示该层领先的是哪个疾病；低质量读出或缺失用独立标记。
3. **正确疾病领先幅度热图：**同样的层×轮次坐标，正负色表示正确疾病领先或落后；固定色标，不逐病例自动美化。
4. **关键转向图：**在指定证据前后，比较attention和MLP阶段的疾病分差变化，旁边列实际回答。

整体再交付12例的首次命中、稳定命中、回退、恢复及最终错误表。全部病例都给，不只展示转向好看的例子。模型最终没有猜中的病例保留；不把最终数据标签当成中间每一轮唯一合理判断。

**这套设计要得出的判断是具体的：哪条证据，让哪些层，朝哪个疾病，移动了多少；这种移动随后被保留、纠正还是放大。** 它与此前报告是否可用的任务不同。
